Atue como um Desenvolvedor Full Stack Sênior. Preciso que você desenvolva a solução completa para um desafio técnico de entrevista de emprego. O projeto é um sistema de gerenciamento de reservas para salas de reunião de um coworking.

Daqui em diante, seguem as minhas instruções e restrições para realizar este desafio. Leia com atenção e gere o código e as instruções de acordo com os parâmetros abaixo.

1. Stack Tecnológica Obrigatória
Front-end: React + Vite + TypeScript.

Back-end: Python (utilize FastAPI ou Flask) + SQL (utilize SQLite para rodar 100% localmente sem necessidade de infraestrutura externa ou Docker).

2. O Desafio e Requisitos Funcionais
A aplicação web deve gerenciar as reservas das salas de reunião e conter as seguintes funcionalidades:

Listagem: Exibir as reservas agrupadas por dia e em ordem cronológica.

Criação: Permitir criar uma nova reserva informando: Sala, Título, Horário de Início e Horário de Fim.

Cancelamento: Permitir cancelar uma reserva existente.

3. Regras de Negócio e Validações
Os campos Sala, Título, Início e Fim são estritamente obrigatórios.

O horário de fim precisa obrigatoriamente ser posterior ao horário de início.

Regra de Sobreposição (Crucial): Duas reservas na mesma sala não podem se sobrepor no tempo. Essa validação deve ser feita e garantida no back-end.

Salas: Não é necessário criar um CRUD para as salas. Elas podem ser fixas no código ou geradas por um seed inicial no banco de dados SQLite.

4. A Decisão Arquitetural (Cancelamento)
O coworking precisa poder cancelar uma reserva.

Você deve implementar o cancelamento utilizando a abordagem de Soft Delete (marcar a reserva como cancelada adicionando uma coluna status ou canceled_at no banco) ou Hard Delete (remover o registro permanentemente do banco).

Escolha uma das abordagens, implemente-a no código e, obrigatoriamente, escreva um texto justificando os prós e contras da sua escolha técnica. Este texto deverá ir para o README.md.

5. Restrições de Ambiente
Execução Local: A aplicação deve ser fácil de rodar localmente. Não utilize Docker, containers ou bancos de dados em nuvem. O banco deve ser um arquivo local .db gerado pelo SQLite.

Simplicidade: O foco é a qualidade do código, tipagem correta no TypeScript, organização de pastas e o cumprimento das regras de negócio.
